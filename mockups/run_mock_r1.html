Your calls

  1. Entry: both? Run in the file sheet (1a) plus a Run tile that opens Files in pick mode (1b). The tile is just a shortcut; it lands in the same flow.
  2. Auto Z probe: left out. It probes Z once at the path origin plus an offset and re-zeros Z, which your 3D probe already does. Easy to add back to Checks later.
  3. Time-lapse: left as "later". Neither the app nor the Wi-Fi board firmware shows how Studio turns it on (the app's own time-lapse page says "coming soon").
  4. Remember settings: the Checks choices remembered between runs (like Studio), origin always defaulting to "keep"?

What Studio's Set Stock and Set Origin really do

  • Set Stock (Anchor1 / Custom) only places the stock in Studio's 3D view, which is why nothing changes. Dropped.
  • Set Origin "Relative to" picks the reference the X/Y offset is measured from: Anchor 1 (a fixed point on the bed) or Current Pos (the spindle). Your two screenshots are the same origin both ways: 19.330 from Anchor 1 = −170.360 from where the spindle was. Anchor 2 is greyed in Studio on the Z1 ("not available for current machine").
  • Same As CAM = the "X Offset / Y Offset … from anchor 1" lines the Carvera community post writes in every file's header (yours says 0, −3), so it works with plain Fusion output.

What Start sends (from Makera's app and the firmware source)

Originonly if you changed it: G10 to G54 (anchor 1 + offset, or the current position)
Checksbuffer M495 X Y C D A B I J H P1: X/Y = toolpath min, C/D = max, A/B = size, I/J = grid points, H = clearance. Leave a letter group out to skip that check. Sent only if a check is on.
Startplay /sd/gcodes/<file>
Assistsent when flipped: M331/M332 vacuum, .1 blow, .2 bed clean, .4 anti-static. State read from the status line's S: fields 4, 7, 8, 10.

How "buffer" works: the Z1 queues the line and runs it at the start of the next play, before the file's first line. So the margin scan and leveling happen inside the job, and Hold / Reset work on them as usual.

Firmware rules the flow has to respect

  • M495 and play both need the machine homed; M495 is ignored otherwise.
  • With a cutter in, M495 does a manual change to the probe first, then calibrates it, and the job's own M6 swaps back. With the probe in but not calibrated it stops with "Probe not calibrated".
  • The margin scan only traces with the laser (no touching); leveling probes the grid with G32 and the firmware applies it live, the file isn't changed.
  • "Fits the travel" is our own check of the toolpath box against the machine's limits (Makera's app does the same before starting).

Not verified yet

  • The exact order Studio sends origin / buffer / play in, and whether it adds anything else (e.g. a time sync). Checking needs a capture of Studio starting a job: a no-motion file with all checks off would do. I'll ask before running anything.
  • What P1, O0 and R0 change on the Z1's own firmware (the app adds them; the community source says P = "go to clearance, then the path origin" after the checks).
  • Where to read Anchor 1's position: the Z1's config has it (−190.69, −194.58 on yours).
  • Download time is from the PC (≈150 KB/s); the phone should be similar.

How the pendant knows (already in its status parsing)

  • State Tool = the Z1 is waiting at the change spot (firmware M490.1).
  • T: = in the collet, its length offset, wanted. From your 2026-11-15 job: T:4,-7.099,1 = T4 in, T1 wanted.
  • P: stays through the wait, so the job, its line and progress are known too.
  • Continue sends M490.2, the same as Makera's app and a short press of the machine's button. Either one clears the popup on every phone.
  • Hide shrinks it to the existing strip in the job panel; tapping the orange pill brings it back.

Not covered

  • A phone that's off or asleep can't be told. Waking it would need a notification service running in the background; say if you want that later.

What the Z1 lets us do (all on its Wi-Fi board, nothing touches motion)

Listls -s /sd/gcodes: name, size, date per entry (what Studio uses)
Deleterm; on a folder it deletes everything inside
Renamemv from → to
New foldermkdir
Upload / readthe upload and download we already have working
Runplay <file> exists; not in version 1

From the ESP32 firmware's own command table. The exact argument formats for rm and mv need a live check before building.

What I'd do

  • Folder icon in the top bar as the way in, like Console and Settings. A tile can be lost when you rearrange tiles; a file browser shouldn't be. Offer "Files" as a tile type too if you like it.
  • Full-screen Files page like Console: list, tap for a sheet, hold to multi-select.
  • Safety: nothing that writes (upload, delete, rename) while the Z1 is running or paused, the playing file can never be touched, and deleting always asks once.
  • Upload uses the phone's system picker, so files can come from Downloads, Drive, email, wherever. Names get the same clean-up as the Fusion plugin (spaces → _).
  • Run later drops into the sheet's first button; the job drawer already handles a running job.

Decided (your answers)

  1. Way in: the top-bar folder icon; the machine name gets smaller.
  2. Rename is in version 1.
  3. Browse into folders and create new ones.
  4. Keep the tool list, as "Job info" with stock and zero too (no cut extents).
  5. Name clash on upload: ask each time.
  6. Newest first.

Running from a folder inside gcodes

Yes, as far as I can see: play takes a full path, the Z1 reports the playing file by its full path, and Makera ships an Examples folder inside /sd/gcodes whose files are meant to be run. I'd prove it on the machine with a file that has no moves in it before relying on it.

Where "Job info" comes from

  • Already in every file you post (the Makera post writes it): stock height, Z zero (e.g. "Stock Top"), cut depth, the tools.
  • Not shown: the stock's X × Y size. Fusion's post output doesn't carry it (only the height and Z zero), and the pendant only shows what a normal post writes.
  • Files from elsewhere (or posted before that change): Job info shows the thickness and says the size isn't in the file (3b).
